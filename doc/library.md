# Standard library

Bo starts with kernel primitives only; the command-line programs then load
`include/core.bo` (skip it with `--bare`). It installs
the default-stack wrapper of every selected-stack primitive: lowercase for
spelled names such as `unit` and `drop`, and a symbol alone where one exists,
such as `+` for `ADD` and `=` for `EQUAL` (a symbol has no uppercase form, so it
cannot be confused with the primitive and no spelled twin like `add` is
defined). Every wrapper is an ordinary, unlocked definition such as
`(() ADD) (+) PUSH`. Focused library
modules (`stack`, `logic`, `control`, `math`, `list`, `value`, `dict`, `stream`,
`io` and `error`) need `core.bo` and define plain lowercase ops
directly: for example, `include/list.bo` defines `map`. `include/std.bo` loads
all the focused modules. `require` loads a source file only once: requiring a file that was already loaded does nothing, so modules can list their dependencies freely and a program may require `std.bo` again. A file whose load ended in an error does not count as loaded, so requiring it again after a fix runs it. `include` (the default-stack op of the primitive `INCLUDE`) always executes the file, discarding its private ops first, which is how to reload it; use it only for files that can run twice. On a machine that started with `--bare`, load `core.bo` with `() INCLUDE` first, since `require` is defined there. `PUSH`, `POP`, `TOP`, `SNAPSHOT` and `DEPTH` transfer
values between named and default stacks.
Examples:

```
(0 pick)            (dup)  PUSH
(1 roll)            (swap) PUSH
; `+` initially has the definition (() ADD)
"subtraction doubles as comparison" drop
    ((swap -) (1) (0) ifte)
    (<)
PUSH
(0 swap -)          (neg)  PUSH
(stdout write)        (emitc) PUSH
```

The tables below are generated by `tools/bodoc.py`: primitive adapters come
from `include/primitives.json`, and derived ops come from documentation
comments in focused `include/` modules. Private helper ops (starting with `__`, see [private ops](language.md#private-ops)) are omitted.
Maintain this introduction and the `include/primitives.json` metadata; do not
edit the tables in `library.md` by hand.

Notes on the standard library:

- List elements are represented by **units**: `(1 2 3) unconsl` gives `(2 3) (1)`; `nth` and `sel` return units, and `ins` accepts one. `apply` evaluates a unit, executing its element if it is an op. `unittype` inspects it without execution.
- The focused `Value` module provides total predicates for numbers, lists, units, integral values, and stack keys; `std.bo` forwards them as `isnumber`, `islist`, `isunit`, `isinteger`, and `isselector`.
- Comparison ops return `1`/`0`.
- `ifte` runs its condition as a program; `branch` takes a truth value already on the stack (`b (then) (else) branch`, as in Joy), and `when`/`unless` run a single program on a true/false value.
- `group` and `groupby` gather *consecutive* elements only, as in Haskell: `(1 1 2 1) group` gives `((1 1) (2) (1))`; sort first to gather all equal elements.
- `unfoldl`/`unfoldr` take `L B ( stop ) ( step )`: the stop test is run on the seed and leaves a truth value (so it normally starts with `dup`), then each `step(B)` is added to `L`; only `L` is left, as the final seed is dropped.
- The iterating ops (`foreach`, `map`, `filter`, `foldl`, `foldr`, `partition`, `sortby`, `groupby`, `zipwith`, `unfoldl` and `unfoldr`, and `times`, `dip`, `keep` and `bi`) keep their own state off the default stack. Their callback finds the caller's stack right below its arguments, as in Joy and Factor: `0 (1 2 3) (apply +) foreach` leaves `6`, and `10 (1 2 3) (apply over + unit) map` leaves `10 (11 12 13)`. `map` and `filter` take the top that the callback leaves as its result; anything else it leaves, or takes, stays changed on the caller's stack.
- `puts` returns nothing; `open` takes a mode string ([primitives](primitives.md)); `INPUT`, `OUTPUT`, `PEEK`, `FLUSH`, `SEEK` and friends are not provided yet.
- `//` is floor division.
- `lambda` and `rec` run a program and re-enter it (anonymous recursion); they wrap the kernel primitives `LAMBDA` and `REC`, see [examples](examples.md).

### Dictionary keys

`tagkey` takes a value and a selector, such as `40 (FIBMEMO) tagkey`,
and returns a named-stack selector. Repeated calls with equal values and the
same tag return equal selectors; distinct values or tags produce distinct
selectors. The tag is checked with `name`. Values may contain numbers, ops
and nested lists. Strings are lists and compare as lists, so `"abc"` and
`(97 98 99)` select the same entry.

The generated op name is `<tag>.<payload>`. The payload is unpadded
Base64URL of the canonical byte encoding below. The final dot separates the
tag, which may itself contain dots, from the payload. Generated keys share the
ordinary op namespace and can be accessed or changed directly, so choose tags
that do not clash with other names.

Unsigned integers below use base-128 little-endian groups with a continuation
bit in each non-final byte:

- A number is `N`, a sign byte (`0` or `1`), an unsigned exponent, and an
  unsigned significand. Zero uses sign, exponent and significand all zero.
  Otherwise the exponent is the binary exponent plus 1074, and the significand
  is the exact integer from `2^52` through `2^53-1` such that the absolute
  value is significand times `2^(exponent - 1074 - 52)`.
- An op is `O`, its Unicode code points as unsigned integers, and a zero
  terminator. Valid op names do not contain NUL.
- A list is `L`, each element encoded recursively, and `E`.

The encoding preserves structural equality and canonicalizes signed zero.
It is not a hash: constructing and looking up a selector has a cost dependent
on the value's size, even though named-stack lookup uses a hash table.
